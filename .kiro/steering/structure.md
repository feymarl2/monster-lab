## Frontend vs serverless split
- Frontend (browser): `app/page.tsx` and `components/*`. Paste box, stitch animation, verdict display, copy/share. The browser makes exactly ONE request: `POST /api/verdict`. No secrets, no direct third-party calls from the browser.
- Serverless API: `app/api/verdict/route.ts` and `lib/*`. Runs all 5 checks server-side in parallel with per-check timeouts, scores, caches (60s), and returns one JSON verdict.
- Single route, single request, single response. No streaming in v1. The one-by-one stitching (~600ms apart, fixed order HEAD, HEART, LEFT ARM, RIGHT ARM, LEGS) is a client-side reveal animation over the already-complete verdict.
- Only `lib/sources/*` modules talk to third-party services. `lib/scoring.ts` is pure (no I/O) so it is easy to reason about and test.

## Naming conventions
- React components: PascalCase files and exports in `components/` (`BodyPart.tsx`).
- Library modules: lowercase single-word filenames in `lib/` and `lib/sources/` (`goplus.ts`, `scoring.ts`).
- Functions and variables camelCase; types and interfaces PascalCase; constants UPPER_SNAKE_CASE (`BSC_RPC_ENDPOINTS`).
- Each source module exports one main function named `check<Source>` (e.g. `checkSourcify`) returning a common result shape: `{ state: "healthy" | "rotten" | "unknown", finding: string, evidenceUrl?: string, data? }`.
- Addresses are normalised to lowercase for cache keys and GoPlus lookups; validated as `^0x[0-9a-fA-F]{40}$` before any request.
- TypeScript strict mode; no `any` for external API responses (narrow unknown JSON defensively).
- Tailwind utility classes; theme tokens live in `globals.css`.

## The /.kiro directory
- `/.kiro` is generated by Kiro through its spec workflow (specs, steering, hooks) and lives at the repo root.
- It MUST be committed. NEVER add `.kiro` or `.kiro/` to `.gitignore` (or any ignore file); gitignoring it can disqualify the submission.
- Specs live in `.kiro/specs/<feature>/` (`requirements.md`, `design.md`, `tasks.md`); steering in `.kiro/steering/`; hooks in `.kiro/hooks/`.
